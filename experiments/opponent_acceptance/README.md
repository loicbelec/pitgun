# Catalog 1.9 opponent acceptance

This experiment is the governed balance-acceptance gate for the opponent policy
used by `pitgun-game`. A successful weekend in staging proves integration; this
matrix separately measures whether controlled player decisions are challenged
across representative circuits and progression.

## Input boundary

The builder consumes the immutable public corpus generated by
`loicbelec/pitgun-game` at revision
`fccffba05b5047afbfba797adaf105d6a2de5d11`. It validates both the complete file
SHA-256 and the corpus's internal artifact digest before materializing any run.

The matrix contains:

- five governed circuit classes: Monza, Monaco, Budapest, Suzuka and Singapore;
- early, mid and late economy-backed budgets: 4, 27 and 37 points;
- three deterministic seeds;
- naive, balanced and circuit-informed controlled player references;
- 45 identical opponent fields and 135 total race requests.

Inside each paired field, only the controlled player's decisions change. The
nine opponent contracts, their component composition, circuit, progression and
seed remain identical.

Every scenario delegates its initial load and consumption coefficients to the
immutable Catalog 1.9 fuel contract. A client-provided fuel override is rejected
at campaign-build time as well as by Model 0.15 execution.

## Build and verify

Check out `pitgun-game` as a sibling repository, then run from the Framework
root:

```bash
python3 experiments/opponent_acceptance/build_campaign.py
python3 experiments/opponent_acceptance/build_campaign.py --check
python3 -m unittest discover \
  -s experiments/opponent_acceptance \
  -p 'test_*.py' -v
cargo build -p pitgun-cli
python3 experiments/opponent_acceptance/run_preflight.py
```

The browser-only `style` and `points` helper fields are removed at the documented
Rust wire boundary. No other request value is reconstructed or tuned in Python.
Every resolved scenario is committed under `scenarios/`, while the immutable
Databricks plan and checksum live under `experiments/databricks/campaigns/`.

The native preflight executes Monza/early/naive, Budapest/mid/balanced and
Singapore/late/circuit-informed twice each through `pitgun run racing`. It
requires byte-identical retries and records only compact standings, budget and
lineage evidence under `results/`. This is an integration and determinism gate,
not the 135-run balance verdict.

## Governance

This campaign contains authored public inputs only. It cannot ingest private
player data, mutate the opponent policy, or promote a game/catalog release.
Databricks execution and the read-only acceptance notebook remain separate,
reviewed steps. The final decision must be explicitly recorded as `ACCEPT`,
`REFINE`, or `REJECT` by a human reviewer.
